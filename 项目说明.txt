# Task: Develop a "secure-at-generation" code generation Skill

## I. Project Background

In current vibe-coding (AI free-form code generation) scenarios, LLMs often ignore security and produce code containing vulnerabilities (such as SQL injection, command injection, hard-coded keys, etc.). I need you to develop a **Skill / plugin** that is not "generate first, check later", but **guides the model to write secure code during the code generation process**.

## II. Core Goals

Develop a security-generation Skill written in Python with the following capabilities:

1. **Security context construction**: dynamically build a System Prompt containing secure coding rules based on the user's task description, language, and framework.
2. **Real-time security validation**: validate model-generated code in milliseconds (based on AST + regex) to detect dangerous patterns.
3. **Automatic repair loop**: when validation fails, feed the violation information back to the model for regeneration, at most 3 retries.
4. **Logging**: fully record the inputs, outputs, validation results, and retry counts of each generation, making later iteration easier.
5. **Iterable rules**: security rules are stored in YAML/JSON files and can be added, removed, or modified at any time without touching the core code.

## III. Technical Constraints

- Use Python (ask me about the version)
- Do not depend on heavy external tools (no Semgrep, etc.), but you may call the agent's additional compute (e.g., OpenAI / Claude) for code generation
- The rule engine is based on Python's `ast` module + regular expressions
- Security rules, forbidden patterns, and safe templates are stored separately as YAML or JSON files
- Provide a clear log format (JSON) for later analysis

## IV. Functional Requirements (Detailed)

### 1. Security Context Builder
- Input: `task\_description`, `language`, `framework`, `context`
- Output: the constructed `system\_prompt` and `user\_prompt`
- Rule source: loaded from YAML files and filtered by language/framework
- The prompt must include:
  - Role definition (secure coding expert)
  - General security rules checklist
  - Rules specific to the language/framework
  - Forbidden pattern blacklist
  - Secure code templates (few-shot examples)
  - Output format requirements (self-check checklist)

### 2. Real-time Security Validator
- Input: code string, language type
- Output: validation result (passed / failed), violation list (rule ID, code line, description)
- Detection items must include at least (not limited to):
  - Dangerous function calls (`eval`, `exec`, `os.system`, `subprocess.call(shell=True)`, `pickle.loads`)
  - SQL string concatenation
  - Hard-coded keys/passwords
  - Plaintext HTTP links
  - Insecure random number generation

### 3. Automatic Repair Loop
- When validation fails, feed the violation information back to the LLM as error feedback
- Ask the LLM to regenerate the code, up to 3 times
- If the 3rd attempt still fails, output the original code + a full vulnerability report, marked as "needs human repair"
(This technique does not necessarily have to rely on this principle — it is just my current idea. Do you have any new, more efficient ideas?)

### 4. Logger
- Recorded fields: timestamp, task description, language, framework, context, first generated code, validation result, retry count, final code, whether the user manually modified it, modification diff
- Output in JSON Lines format

### 5. Rule File Structure
- `rules/general.yaml`: general security rules (cross-language)
- `rules/python.yaml`: Python-specific rules
- `blacklist/python.yaml`: Python dangerous pattern blacklist
- `templates/python/`: secure code templates (grouped by function, e.g., auth.py, db.py, file_upload.py)

## V. Deliverables
